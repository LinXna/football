# YBTY 与雷速队名关联对齐纠错与防机械替换改造计划

## 1. 核心原则与背景纠偏
在原实现中，系统存在严重的逻辑漏洞：
- **机械 100% 盲信**：只要底层 `team_aliases.json` 存在一条映射（哪怕是被误存的两个完全不同的队名，如门兴 vs 皇家社会），系统就机械式给出 100% 匹配；
- **偷换雷速队名**：错误绑定导致本属于雷速其他比赛（如皇家社会 vs 美因茨）的雷速队名被强行替换挂载到 YBTY 门兴上，造成雷速真实队名被篡改替代。
- **纠偏声明**：**不引入任何外部“法定俱乐部集合”或第三方词典**。全系统完全且仅立足于 **YBTY 原始队名** 与 **雷速原始队名** 的真实映射关系。

---

## 2. 详细改造方案

### 模块 1：雷速原始队名保真与别名有效性字根验真（拒绝机械 100%）
- **文件**: `refactor/02_canonical_model/matchAligner.ts`
- **核心逻辑**:
  1. **雷速原始队名绝对保真（严禁替换）**：
     - 在 Canonical 模型及卡片展示中，雷速的队名必须永远忠实记录其源头导出的原始名称（`leisu_home_name`, `leisu_away_name`），任何情况下不得在底层被替换或改写；
     - 无论是 YBTY 还是雷速，原始名称必须在对齐结果中原样呈现，绝不发生“门兴被偷换为皇家社会”的现象。
  2. **别名关联有效性二次验真（防机械 100% 假匹配）**：
     - 别名的合法本质是“同一支球队在 YBTY 与雷速两端的翻译简称/别称”（如：`多特` ↔ `多特蒙德`、`布莱顿` ↔ `布莱顿及霍夫阿尔比恩`）；
     - 当系统查询别名库命中时，**严禁无脑直接赋 100 分**！
     - 系统必须执行两端原始名称的字根与语义合理性校验：
       若 YBTY 原始队名与雷速候选原始队名**字面完全无关联（文字相似度为 0 且无共享字根）**（例如：`门兴格拉德巴赫` vs `皇家社会`、`曼城` vs `布莱克本`）：
       - **判定为“历史错误绑定/脏别名”**；
       - **直接剥夺 `is_alias_exact_hit` 资格**；
       - **置信度强制归零（0 分），判定为 `UNMATCHED`**；
       - 标记异常原因：“⚠️ 拦截疑似历史错误别名：YBTY [门兴格拉德巴赫] 与雷速 [皇家社会] 毫无字面关联，已阻止机械 100% 误匹配与错误替换”。

### 模块 2：导入数据时的队名比对与异常纠错机制
- **文件**: `src/components/CanonicalMatchCenter.tsx` 与导入向导
- **核心逻辑**:
  1. **比对时暴露真实双源名称**：
     - 在导入数据比对列表中，清晰展示 YBTY 原始队名与匹配到的雷速原始队名，严禁隐瞒或偷换；
  2. **错误绑定高亮与异常提示**：
     - 若检测到底层存在字面相似度为 0 的异常映射，系统在比对列表中以醒目的黄色/红色预警标出：“检测到历史错误绑定”；
  3. **界面一键纠错与物理抹除**：
     - 在比对列表和赛事卡片中，提供【纠正/解除关联】按钮；
     - 点击解除时，弹出确认框：【解除关联并彻底物理从别名库中删除该错误映射】；
     - 触发调用后端 `DELETE /api/aliases`，物理擦除 `team_aliases.json` 中的脏记录，从源头消灭错误。

### 模块 3：别名库防投毒与写入拦截（源头防患）
- **文件**: `server/routes/aliasReadRoutes.ts` 与 `src/components/CanonicalMatchCenter.tsx`
- **核心逻辑**:
  1. **写入前置拦截**：
     - 在自动沉淀别名（批量或单条）及手动添加别名时，校验 YBTY 与雷速名称。如果两者字面相似度为 0 且用户未显式确认强行绑定，系统自动拒绝写入并抛出预警，彻底杜绝对立比赛的客队被写为主队别名。

---

## 3. 验收标准与验证方案
1. **零相似度别名验真自测**：
   - 即使人工故意在 `team_aliases.json` 写入 `"门兴格拉德巴赫": ["皇家社会"]`，导入德甲赛事时，系统自动识别出无字根关联，判定为脏别名，置信度直接判定为 0 分（UNMATCHED），绝对不再出现机械 100%！
2. **雷速原名展示保真验证**：
   - 验证雷速原始数据中的队名在任何展示与参考引用中均为真实队名，绝不发生队名被替换的情况；
3. **一键纠错抹除验证**：
   - 在界面点击解除错误关联，确认物理删除，检查 `team_aliases.json` 该错误记录被完全抹除。
