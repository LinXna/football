# 05. 系统测试与验证指南 (Verification & Testing Guide)

## 一、 测试目标与验证策略

为确保系统全面迁移至 `StandardMatchData` 新数据结构后稳定、精准运行，杜绝老数据问题再次复发，本指南提供了完整的测试用例矩阵、自动化验证方法与人工视觉核验流程。

测试覆盖三大核心维度：
1. **数据管道完整性与字段契约测试 (Pipeline & Schema Conformance)**
2. **算法逻辑与风控硬性规则测试 (Algorithm & Risk Gate Testing)**
3. **前端组件渲染与异常流容错测试 (UI Component & Boundary Testing)**

---

## 二、 测试用例矩阵与标准验证流程

### 1. 数据解析与归一化测试用例 (TC-NORM)

### 2. 风控与推荐决策规则测试用例 (TC-RECOM)

| 用例编号 | 测试场景 | 输入状态特征 | 预期输出与风控判定 |
| :--- | :--- | :--- | :--- |
| **TC-RECOM-01** | 未校验比分硬性拦截 | `score_verified == False` | **严禁评 A 级推荐**；评级强制封顶为 B- 或 RESEARCH，标注 `UNVERIFIED_SCORE_RISK`，且不结算剩余进球盘。 |
| **TC-RECOM-02** | 四分之一盘口（0.25/0.75）判定 | 让球 `+0.25`、`-0.75` 或大小球 `2/2.5`、`2.5/3` | 准确拆分为双半盘，输出清晰的赢半、输半与走盘规则提示，数值盘位精确。 |
| **TC-RECOM-03** | 电竞与模拟赛事过滤 | 联赛或队名含 "EAFC"、"电竞"、"模拟" 等关键字 | 直接在初筛阶段拦截剔除，不进入候选与推荐清单。 |
| **TC-RECOM-04** | 红牌事件动态走势评估 | 统计或文字直播中出现红牌事件 (`red_cards > 0`) | 触发红牌重估加分，并在推荐理由中显著标明受罚方与人数。 |
| **TC-RECOM-05** | 攻守动量时序指标融合 | 双方动量出现单向压制（如近 15 分钟持续高压） | 动量趋势被纳入综合推荐打分，并在推荐详情中呈现支撑依据。 |

## 三、 自动化验证与构建执行命令

在完成代码修改后，必须依次运行以下命令进行工程级校验：

```bash
# 1. 执行 TypeScript 静态类型检查与代码风格校验
npm run lint

# 2. 执行前端生产环境打包构建（验证无编译阻断错误）
npm run build
```

## 四、 验收封板标准 (Sign-off Criteria)

系统重构完成的最终验收必须同时满足以下 5 项硬性指标：

1. **零老数据残留**：全系统代码中不再存在 SofaScore 遗留字段名，全面使用 `StandardMatchData`。
2. **数据链路全畅通**：雷速新接口导出的 `results[].formal` 结构能够从扩展端顺畅流经 Python 管道，并在前端各组件完美呈现。
3. **风控规则 100% 落实**：所有推荐硬性约束（未校验比分拦截、电竞过滤、YBTY 队名基准、四分之一盘精确计算）均有防御代码并测试通过。
4. **编译与 Lint 完全通过**：`npm run lint` 与 `npm run build` 均执行成功且无报错。
5. **界面交互零异常**：各页面与弹窗在处理缺失数据或极值情况时均有优雅降级，无白屏或崩溃。
